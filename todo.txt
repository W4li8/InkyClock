[2026-09-27 01:35] Investigated "clock is off" report: NOT a code bug. Root
  cause was my own repeated mpremote exec/run/fs-cp commands during earlier
  testing, each of which sends a break to grab REPL control -- one of these
  landed mid boot-time sync_blocking(), killing it before the RTC got set,
  after which the board just sat idle (main() dead) with the RTC frozen at
  its 2021-01-01 power-on default, ticking correctly but from a stale base.
  Verified conclusively: (1) RTC advances at exactly 1:1 with real elapsed
  time (two reads 8s apart differed by exactly 8s) -- so the RTC hardware
  itself is fine; (2) a clean single reset + fully undisturbed 15s wait
  produced an RTC reading 6s off (just sync latency) matching real time.
  No fix needed in the shipped code; this only happens when something is
  actively sending serial breaks to the board, which normal unattended
  operation never does.
